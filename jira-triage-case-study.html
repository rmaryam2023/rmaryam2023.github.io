ML-Based Jira Triage & Release Automation

Role Lead Engineer / Project Manager
Timeline 4 months (Capstone)
Impact 75% time reduction
Company ThreatConnect (Dataminr)
React Node.js Gemini AI Jira REST API AWS Google Apps Script JQL Machine Learning Slack API

The Challenge

ThreatConnect's three-person documentation team was drowning in manual triage work. Every quarter, they manually reviewed 350+ Jira tickets to determine which required documentation updates—a process that consumed 3-4 hours per cycle and involved tedious copy-paste between Jira and Google Sheets.

  • Manual data transfer: Copy ticket details from Jira → paste into Google Sheets → categorize → prioritize
  • Time-intensive review: 3-4 hours spent reading ticket descriptions to understand what documentation needs updating
  • Context switching: Constant back-and-forth between Jira, Google Sheets, and knowledge base
  • Missed tickets: In the rush, some high-priority tickets fell through the cracks
  • No automation: Despite using Jira Automation for some workflows, triage remained entirely manual
Core Problem: How do we eliminate manual data entry, automatically prioritize tickets, and leverage AI to suggest which knowledge base articles need updating—all while integrating seamlessly with existing Jira workflows?

The Solution

I led a Capstone team to build a web-based AI-powered triage dashboard that integrates Jira, Gemini AI, and Google Apps Script to automate 75% of the documentation team's triage workflow. The system was designed around a key constraint: we couldn't replace or redesign existing Jira infrastructure—only augment it.

System Architecture: 5 Core Components

1. Custom Dashboard

Centralized React-based interface displaying all Jira tickets with advanced filtering by status, priority, date, and assignee. Eliminates the need for Google Sheets entirely.

2. Jira API Integration

Bidirectional sync using Jira REST API. Dashboard pulls ticket data automatically, and any changes made in the dashboard update the corresponding Jira ticket in real-time.

3. Gemini AI Engine

Analyzes ticket content to generate summaries, categorize urgency, and recommend specific knowledge base articles that need updating based on ticket context.

4. Role-Based Access Control

Secure authentication system that restricts dashboard access based on user roles (viewer vs. editor) to protect sensitive ticket data.

5. Notification System

Proactive alerts via dashboard and Slack when new high-priority tickets arrive or when errors are detected (missing data, null tickets).

How It Works: The Triage Workflow

Step 1: Automated Ticket Ingestion

When a new Jira ticket is created or updated, the dashboard automatically pulls it via Jira REST API using JQL (Jira Query Language) queries. Key data extracted:

  • Ticket ID, status, priority, assignee
  • Issue type (bug, feature, enhancement)
  • Description, comments, linked issues
  • Labels and custom fields (e.g., "documentation-required")

Step 2: AI-Powered Analysis

Gemini AI processes each ticket through a multi-stage pipeline:

  • Summarization: Condenses long ticket descriptions into 2-3 sentence summaries
  • Categorization: Classifies tickets by urgency (high/medium/low) and documentation impact
  • Article Matching: Uses semantic search to identify which existing knowledge base articles are affected
  • Recommendation Generation: Suggests specific actions ("Update API authentication article with new OAuth flow")

Step 3: ML-Based Anomaly Detection & Prioritization

Built a lightweight classification model that learns from historical triage decisions to flag high-risk tickets:

  • Analyzes patterns: tickets with specific labels + high comment count = urgent
  • Detects anomalies: tickets sitting idle for >7 days without triage
  • Prioritizes based on business impact: customer-facing features ranked higher

Step 4: Dashboard Presentation & User Action

Documentation team sees a clean interface with:

  • AI-generated summary at the top of each ticket card
  • Suggested knowledge base articles with confidence scores
  • One-click actions: "Mark as triaged," "Assign to writer," "Update article"
  • Real-time status sync back to Jira

Technical Implementation

Frontend: React Dashboard

Built with React for responsive, real-time UI updates:

  • Component architecture: TicketCard, FilterBar, AISummaryPanel, ArticleRecommendations
  • State management: React Context API for global ticket data
  • Real-time updates: WebSocket connection for live Jira sync
  • Filtering & search: Client-side filtering by multiple criteria (status, priority, AI confidence score)

Backend: Node.js API Server

Express.js server handling Jira integration and AI orchestration:

  • Jira REST API wrapper: Handles authentication, rate limiting, error retry logic
  • Gemini AI integration: Structured prompts for ticket analysis and article matching
  • ML model serving: TensorFlow.js model for anomaly detection runs server-side
  • Caching layer: Redis cache for frequently accessed tickets and AI responses

Jira Integration Strategy

JQL Queries for Smart Filtering:

project = "Documentation" AND 
(labels = "docs-required" OR description ~ "documentation") AND 
status != Closed AND 
created >= -90d
ORDER BY priority DESC, updated DESC

Bidirectional Sync:

  • Dashboard → Jira: When user marks ticket as triaged, API call updates Jira status field
  • Jira → Dashboard: Webhook triggers dashboard refresh when ticket is updated in Jira
  • Conflict resolution: Last-write-wins with user notification if conflict detected

Gemini AI Prompt Engineering

Structured prompts to ensure consistent, useful outputs:

You are a documentation triage assistant for ThreatConnect.

Task: Analyze this Jira ticket and provide:
1. A 2-3 sentence summary of the issue
2. Urgency classification (HIGH/MEDIUM/LOW)
3. List of knowledge base articles that need updating (with confidence %)
4. Recommended action for documentation team

Ticket: [ticket content]

Knowledge Base: [list of article titles and descriptions]

Output format:
{
  "summary": "...",
  "urgency": "HIGH",
  "affected_articles": [
    {"title": "API Authentication", "confidence": 0.92, "reason": "..."}
  ],
  "recommendation": "..."
}

ML Anomaly Detection Model

Trained a simple classification model on historical triage data:

  • Features: Ticket age, comment count, label combinations, assignee history, update frequency
  • Labels: "Urgent" (triaged within 24h), "Normal" (triaged within 1 week), "Low priority"
  • Model: Random Forest classifier (scikit-learn) with 87% accuracy
  • Deployment: Exported to TensorFlow.js for server-side inference

Google Apps Script Automation

Built supplementary automation for release notes generation:

  • Pulls closed tickets from Jira via API
  • Groups by release version using fix version field
  • Generates formatted release notes in Google Docs
  • Automatically shares doc with product team via email

Technical Challenges & Solutions

Challenge 1: Jira API Rate Limits

Jira Cloud enforces strict rate limits (10 requests/second). With 350+ tickets, initial implementation hit rate limits and failed.

Solution:

  • Implemented request batching: fetch 50 tickets per API call using JQL pagination
  • Added exponential backoff with retry logic (3 attempts before failure)
  • Caching layer: store ticket data in Redis for 15 minutes to reduce API calls
  • Background job: refresh ticket data every 30 minutes instead of on-demand

Challenge 2: Gemini AI Response Consistency

Early versions of AI summaries varied wildly in format—sometimes JSON, sometimes plain text, sometimes incomplete.

Solution:

  • Enforced strict JSON schema in prompt with examples
  • Added response validation: reject responses that don't match schema
  • Fallback logic: if AI response invalid, use rule-based summarization (extract first sentence of description)
  • Few-shot prompting: included 3 examples of good ticket→summary pairs

Challenge 3: Knowledge Base Article Matching Accuracy

Initial semantic search for article recommendations had low precision—AI suggested irrelevant articles 40% of the time.

Solution:

  • Pre-processed knowledge base: created embeddings for all article titles + first paragraph
  • Hybrid search: combined semantic similarity with keyword matching
  • Confidence thresholding: only show recommendations with >70% confidence
  • User feedback loop: when team rejects a suggestion, retrain model to avoid that pattern

Result: Accuracy improved from 60% → 87%

Challenge 4: User Authentication & Security

Dashboard needed to authenticate users but couldn't store Jira passwords (security policy violation).

Solution:

  • OAuth 2.0 integration with Jira (users authorize dashboard once via OAuth flow)
  • Role-based access control: query Jira for user's group membership, restrict dashboard features accordingly
  • Session management: JWT tokens with 8-hour expiration
  • Audit logging: all dashboard actions logged for compliance

Architecture Decisions & Tradeoffs

Why React Over Angular/Vue?

  • Team expertise: ThreatConnect's engineering team already uses React
  • Component reusability: built reusable TicketCard components for future features
  • Large ecosystem: easier to find libraries for Jira integration

Why Gemini AI Over OpenAI GPT?

  • Cost: Gemini cheaper for high-volume requests (350+ tickets)
  • Context window: Gemini 1.5 Pro handles longer ticket descriptions
  • Structured outputs: Gemini's JSON mode more reliable than GPT function calling

Why Host on AWS vs. Internal Infrastructure?

  • Scalability: AWS auto-scales during high traffic (e.g., end-of-quarter ticket surge)
  • Managed services: Lambda for serverless functions, RDS for database, reduces ops overhead
  • Security: AWS security groups + VPC isolation meet ThreatConnect's compliance requirements

Key Learnings

What worked well:

  • User-centered design: Weekly feedback sessions with documentation team caught UX issues early
  • Incremental rollout: Launched with core features (Jira sync + AI summaries) first, added ML prioritization in phase 2
  • API-first approach: Building REST API separate from React frontend allowed faster iteration
  • Constraint as feature: "Can't replace Jira" constraint forced us to build a complementary tool, not a competitor

What could be better:

  • Earlier performance testing: Discovered rate limit issues late in development; should have load-tested with 500+ tickets from day one
  • More AI fallbacks: When Gemini API is down, entire dashboard becomes less useful. Should have rule-based backup for critical features
  • Better error messaging: Early versions showed generic "API error" messages; v2 added user-friendly explanations
